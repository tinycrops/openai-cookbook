Agentic Information System: Signal Recording Flow

This diagram illustrates how demo.py interacts with SignalRecorder to record and fetch signals in signals.db.

Detailed Explanation

Below is a step-by-step walkthrough of how the demo script and SignalRecorder work together:

1. demo.py (Demo Script)

  • Imports SignalRecorder from signal_recorder.py.
  • Creates an instance of SignalRecorder, which sets up the SQLite database and table.
  • Calls record_signal to log example metrics (e.g., channel_capacity, episode_reward).
  • Fetches recent records with fetch_signals(limit=10) and prints them.
  • Closes the database connection with close().

2. SignalRecorder Initialization (__init__)

  • Connects to the SQLite database file (default signals.db), with thread-safe configuration.
  • Creates a table named signals if it does not already exist, with columns:
    • id (auto-increment primary key)
    • timestamp (ISO8601 UTC timestamp)
    • signal_name (text)
    • signal_value (numeric, e.g., floats)
    • metadata (JSON-encoded text for additional context)

3. record_signal(name, value, metadata)

  • Generates a current UTC timestamp (ISO format, suffixed with 'Z').
  • Serializes the metadata dictionary to JSON if provided.
  • Inserts a new row into the signals table with a thread lock to ensure safety.
  • Commits the transaction immediately to persist the data.

4. fetch_signals(name=None, limit=100)

  • Constructs a SQL query to select up to limit recent records, optionally filtered by signal_name.
  • Executes the query under the same thread lock.
  • Parses the JSON metadata back into Python dictionaries.
  • Returns a list of dictionaries, each containing id, timestamp, signal_name, signal_value, and metadata.

5. close()

Closes the SQLite connection cleanly under lock. Always call this when done recording.

Database Schema

CREATE TABLE signals (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp TEXT NOT NULL,
  signal_name TEXT NOT NULL,
  signal_value REAL,
  metadata TEXT
);
